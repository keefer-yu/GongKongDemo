# 常见问题

## 启动/运行

### 端口被占用

默认端口：Modbus 15020、MQTT 18830、REST 15080。被占用时：

- 看 `netstat -ano | findstr 15020`；
- 改 `config/devices.json` 的 `port` 或 `config/northbound.json` 的 `mqtt.port` / `rest.url`；
- 上位模拟器用 `--port` / `--rest` 对应改。

### 程序一闪而过（WinExe 看不到异常）

用 `dotnet <dll> ...` 从命令行启动，例如：

```powershell
dotnet demos\WinForms\Scada.WinForms.V1.SeeData\bin\Debug\net10.0-windows\Scada.WinForms.V1.SeeData.dll
```

### 缺少 .NET 10

安装 .NET 10 SDK。`global.json` 固定 10.0.1xx 以上，允许滚动到本机最新的 10.0.x feature band。

## V1/V2 采集

### 点位一直 Bad / ERR

- V1 没启动采集；
- V2 没启动模拟 PLC，且配置指向了不存在的设备；
- IP/端口/UnitId 不对；
- 地址区域不对（HR vs IR vs Coil）。

### 数值差 10 倍 / 100 倍

缩放 `scale` 配错。液位寄存器 418 表示 41.8%，所以 scale=0.1。

### float 数值乱码

字节序不对。依次试 `ABCD/DCBA/BADC/CDAB`，或问 PLC 工程师。

### 断线后多久恢复

采集引擎指数退避：1/2/4/8/10 秒，最大 10 秒。模拟器停止后观察 Bad + 重连日志。

## V3 报警/历史

### 报警不出现

- 故障是否注入成功（看日志）；
- 是否超过延时（默认 2 秒）；
- 质量是否 Good（Bad 值不参与报警）；
- 阈值是否配错。

### 历史库文件打不开/被占用

SQLite WAL 模式会生成 `-wal`/`-shm` 文件。用 DB Browser 打开主 `.db` 即可。程序退出会清池；若仍被占用，关闭程序后再打开。

### 历史行数增长太快

演示每 500ms 写 8 个点。生产应使用变化写入、批量、时序库和保留策略。

## V4 控制

### 命令被拒绝

看“联锁矩阵”的“原因”列。常见：液位低、自动模式、设定值越界、未确认。

### 写入成功但回读不一致

- PLC 扫描周期/生效延迟；
- 写入被 PLC 逻辑覆盖；
- 地址/类型/缩放错；
- 设备只接受脉冲写入。

演示里回读等待 300ms，真实项目应按设备响应调整。

### 急停没有全停

急停是四条命令的顺序执行；看审计表哪一条失败。设备侧还应有硬急停/安全回路。

## V5 北向

### REST 401

请求头加 `X-Api-Key: scada-demo-token`，或改 `config/northbound.json` 的 `rest.apiKey` 并同步上位模拟器。

### REST 409

联锁拒绝。看返回 JSON 的 `InterlockChecks`。

### MQTT 连不上

- 上位模拟器（Broker）是否启动；
- 端口 18830 是否被占用；
- V5 的 “北向” 页看错误；
- 主题前缀是否一致。

### 待补发一直增加

Broker 没恢复。`data/mqtt-outbox.jsonl` 会保留，恢复后自动补发。上限默认 1 万条。

### 上位模拟器 ACK 为 0

- V5 是否已启动并连接；
- Token 是否一致；
- 命令点位是否存在/可写/联锁通过；
- 看 V5 命令审计页的来源 Mqtt。

## 构建/测试

### `dotnet build` 报找不到 `Scada.Control`

确认在仓库根目录执行 `dotnet build ScadaDemo.sln`；不要单独构建未还原的 demo。

### 测试临时数据库删不掉

Windows 上 SQLite 连接池可能短暂占用；测试已做容错清理，不影响结果。

### `--smoke` 退出码非 0

看各 app 的 `data/smoke-*.json` 和 `data/` 日志；V5 需要先启动上位模拟器，或直接跑 `scripts/verify.ps1`。

## 设计相关

### 为什么不用 NModbus？

教学目的：让小白看到 MBAP/PDU 的原始字节。生产请换成熟库。

### 为什么不用 Chart 控件？

避免第三方依赖，WinForms 用 GDI+、WPF 用 `DrawingContext` 各画一个轻量趋势图，代码可读、可改。

### 为什么 SQLite 不用 EF Core？

演示只需要三张表，`Microsoft.Data.Sqlite` 更直接；生产可用 EF Core/Dapper。

### 为什么自动温控在设备侧？

符合工业分工：PID/联锁在 PLC，SCADA 只写设定值和模式；上位机断线不影响设备控制。
