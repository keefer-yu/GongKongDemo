# 版本演进与代码导读

## 依赖阶梯

```text
V1  Core + UI
V2  + Protocol
V3  + Alarms + Storage
V4  + Control
V5  + Northbound
```

每个版本只引用自己需要的工程，所以：

- V1 的 bin 目录里没有 SQLite/MQTT；
- V2 没有报警/控制/北向；
- V3 才出现历史库；
- V4 才出现联锁/命令服务；
- V5 才出现 REST/MQTT。

## 每版新增代码

### V1

- `Scada.Core/Tags/TagModels.cs`、`TagValueCodec.cs`、`TagStore.cs`
- `Scada.Core/Devices/ReactorProcessModel.cs`、`SimulatedDeviceSession.cs`
- `Scada.Core/Acquisition/AcquisitionEngine.cs`
- `Scada.UI.WinForms/Controls/TagCard.cs`、`Scada.UI.Wpf/ViewModels/TagRowViewModel.cs`
- `demos/.../V1.../MainForm.cs|MainWindow.xaml`

### V2

- `Scada.Protocol/Modbus/ModbusPdu.cs`：PDU 编解码
- `ModbusTcpClient.cs`：事务号、超时、异常码
- `ModbusTcpSlave.cs`：MBAP、FC 01/03/05/06/16、TCP 服务
- `ModbusTcpDeviceSession.cs`：点位表 → 块读写
- `PlcSimulatorHost.cs`：工艺模型 + 从站
- `tools/Scada.PlcSimulator`

### V3

- `Scada.Alarms/AlarmEngine.cs`：状态机/死区/延时/确认
- `Scada.Storage/SqliteHistoryStore.cs`：历史/报警/审计表
- V3 UI：报警页、历史页、趋势、故障注入

### V4

- `Scada.Control/InterlockEngine.cs`
- `Scada.Control/CommandService.cs`
- V4 UI：控制页、联锁矩阵、审计、急停、自动模式

### V5

- `Scada.Core/Integration/IntegrationContracts.cs`

- `MqttNorthbound.cs`（MQTTnet 4.3.7）
- `OfflineBuffer.cs`（JSONL 断网补发）
- `NorthboundCoordinator.cs`（把遥测/报警/命令串起来）
- `tools/Scada.UpperSystemMock`（内嵌 Broker + 客户端）

## 怎么“看差异”

```powershell
# 同一版本的两套 UI 对照
code demos\WinForms\Scada.WinForms.V3.AlarmHistory\MainForm.cs
code demos\Wpf\Scada.Wpf.V3.AlarmHistory\MainWindow.xaml

# 相邻版本对照
code demos\WinForms\Scada.WinForms.V2.Modbus\MainForm.cs
code demos\WinForms\Scada.WinForms.V3.AlarmHistory\MainForm.cs
```

WinForms 版本用代码布局（不依赖 Designer），所以相邻版本可以直接 diff；WPF 版本主要 diff `MainWindow.xaml` + `MainViewModel.cs`。

## 阅读建议

- 先看 `Program.cs`/`App.xaml.cs`：对象是怎么 new 出来的。
- 再看 `BuildUi`/`MainWindow.xaml`：界面有哪些区域。
- 再看 `Start...Async`/`Refresh`：数据怎么流动。
- 最后看 `Scada.*` 库：协议/报警/控制/北向的细节。
