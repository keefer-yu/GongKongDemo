# 学习路线

## 15 分钟：先看见一次完整数据流

1. `scripts\run-v1.ps1`
2. 点“启动采集”，看液位/温度/压力变化，点“停止”。
3. 打开 `demos/WinForms/Scada.WinForms.V1.SeeData/MainForm.cs`，找到 `StartAsync`、`RefreshUi`。
4. 回答：扫描周期是多少？为什么坏值显示 `ERR` 而不是 0？UI 线程如何被保护？

## 1 小时：采集 → 报警 → 控制

| 时间 | 动作 | 要看的代码 |
|---|---|---|
| 0–10 min | 跑 V2，观察右侧报文；点“停止模拟（断线）”，看重连 | `Scada.Protocol/Modbus/*` |
| 10–25 min | 跑 V3，点“注入超温故障”，等 HH 报警，确认 | `Scada.Alarms/AlarmEngine.cs` |
| 25–40 min | 跑 V4，低液位启泵被拒；正常启泵看回读/审计；急停 | `Scada.Control/InterlockEngine.cs`、`CommandService.cs` |
| 40–60 min | 跑 V5 + 上位模拟器，看 MQTT ACK 和 REST 写点 | `Scada.Northbound/*` |

## 半天：把 Demo 改成你的设备

1. 按 `docs/07-接入真实PLC.md` 改 `config/devices.json`（IP、端口、UnitId、地址、类型、缩放）。
2. 用 Modbus Poll / QModMaster 先确认寄存器能读。
3. 先用 V2 跑通采集，再逐级启用 V3/V4/V5。
4. 把联锁阈值改成你的工艺值；把设备侧保护也在 PLC 里实现一遍。
5. 用 `--smoke` 和 `scripts/verify.ps1` 做回归。

## 三条阅读线

### 只关心“怎么连设备”

`Scada.Core/Tags/TagValueCodec.cs` → `Scada.Protocol/Modbus/ModbusPdu.cs` → `ModbusTcpClient.cs` → `ModbusTcpDeviceSession.cs`。

### 只关心“界面怎么做”

WinForms：`Scada.UI.WinForms.Controls.TagCard/TrendChart` → `Scada.WinForms.V3.../MainForm.cs`。
WPF：`Scada.UI.Wpf.ViewModels.TagRowViewModel` → `Themes/DarkTheme.xaml` → `Scada.Wpf.V3.../MainWindow.xaml`。

### 只关心“怎么和 MES 对接”

`Scada.Core/Integration/IntegrationContracts.cs` → `RestApiServer.cs` → `MqttNorthbound.cs` → `NorthboundCoordinator.cs` → `tools/Scada.UpperSystemMock/Program.cs`。

## 动手练习

- V1：把周期改 250ms，观察采集次数/延迟；新增一个“搅拌器”点位。
- V2：把 `temp` 的 `byteOrder` 改成 `DCBA`，观察数值乱码；改回。
- V3：把温度 HH 改 90、延时改 5 秒，重新注入故障，观察报警出现时间。
- V4：把 `pumpMinLevel` 改成 30，重新尝试启泵；新增一条“自动模式禁止开阀”的联锁。
- V5：用 `curl` 读点位、写设定值；停掉上位模拟器（Broker），看 `data/mqtt-outbox.jsonl` 增长，再启动看补发。

## 自检问题

1. 为什么采集循环不能直接更新 WinForms 控件？
2. 为什么 `float32` 要占两个寄存器？ABCD 和 CDAB 有什么区别？
3. 报警的死区和延时分别防止什么问题？
4. 为什么“写入成功”还要回读？回读不一致怎么处理？
5. SCADA 联锁和设备侧保护为什么要同时存在？
6. MQTT 的 `cmd/ack` 为什么必须带命令 id？
7. REST 写点和 MQTT 命令最后都走到哪个类？这样设计有什么好处？
