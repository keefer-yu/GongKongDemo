# 代码注释导读

这份工程是给初学者看的，所以代码里刻意保留了较多中文注释。注释分三类：

| 形式 | 用途 | 例子 |
|---|---|---|
| `/// <summary>` | 公共类/方法的“它是什么、什么时候用” | `TagValueCodec.Decode` |
| `// 说明：` / 普通 `//` | 解释“为什么这么写”、容易踩的坑 | MBAP 的 Length 包含 UnitId |
| 段落注释 | 一段流程的阅读顺序 | `AcquisitionEngine.RunAsync` 的“连接→读→写→等” |

## 建议阅读顺序

### 只想看“数据怎么从设备到界面”

1. `src/Scada.Core/Devices/ReactorProcessModel.cs`
   - 看 `Tick`：工艺如何随时间变化；
   - 看 `ReadHoldingRegisters`：寄存器表怎么编码；
   - 看设备侧保护：低液位停泵、超温断加热。
2. `src/Scada.Core/Tags/TagValueCodec.cs`
   - 看 `Decode/Encode`：工程值与原始值互转；
   - 看 `BuildBytes/FromBytes`：float32 的 ABCD/DCBA/BADC/CDAB。
3. `src/Scada.Core/Acquisition/AcquisitionEngine.cs`
   - 看 `RunAsync`：扫描周期、失败标 Bad、指数退避；
   - 看 `StartAsync/StopAsync`：后台任务如何取消。
4. `src/Scada.Protocol/Modbus/ModbusTcpClient.cs` / `ModbusTcpSlave.cs`
   - 看 MBAP 7 字节、事务号、Length、异常响应；
   - 看 TCP 为什么必须“先读头，再按 Length 读剩余”。
5. V1/V2 的 `MainForm.RefreshUi` / `MainViewModel.Refresh`
   - 看 UI 为什么只读 TagStore，不直接读设备。

### 只想看“报警/控制/北向”

1. `src/Scada.Alarms/AlarmEngine.cs`
   - 状态机、死区、延时、确认；
   - 重点看 `Evaluate` 里“活动前/活动后”两个分支。
2. `src/Scada.Control/CommandService.cs`
   - 五层：参数校验 → 串行化 → 联锁 → 写入 → 回读；
   - 重点看“写成功 ≠ 控制成功”。
3. `src/Scada.Control/InterlockEngine.cs`
   - 为什么“危险方向从严、安全方向从宽”；
   - Bad 值为什么按 0 保守处理。
4. `src/Scada.Northbound/NorthboundCoordinator.cs`
   - 遥测/报警/命令如何接线；
   - 为什么 REST 和 MQTT 都走同一个 CommandService。
5. `src/Scada.Northbound/MqttNorthbound.cs`
   - LWT、重连循环、离线补发；
   - 为什么 QoS0 用于遥测。

## 读注释时注意

- 注释解释“为什么”，不是逐行翻译代码；看不懂时先对照 `docs/03`、`docs/04`、`docs/05`、`docs/06`。
- 注释里的数字（500ms、15020、300ms）都和 `config/*.json` 或代码默认值对应，改代码时记得同步。
- 教学版 Modbus 只实现项目需要的功能码；生产请换成熟库，注释里也标了边界。
- 如果你要接真实 PLC，先看 `docs/07-接入真实PLC.md`，不要只依赖注释。
